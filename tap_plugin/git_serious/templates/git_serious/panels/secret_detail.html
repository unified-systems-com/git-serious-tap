What this means

At runtime GitHub substitutes an empty string for a secret that does not exist. The step does not fail; it runs with nothing where the credential should be — a token-less API call, an unsigned upload, a login with a blank password — and the job goes green. Every workflow below runs that way today, for this name.

"Cannot find" is what the grid can say. Whether that is a defect is what the reader knows: on this estate the *_PAT names are vestigial — left in workflow files when the organisation went public and the personal tokens they stood for stopped being needed. A name that is deliberately unset is still a line of YAML that reads as if a credential were there.
